Matching Rules Overview
-----------------------

There are various configurations for Matching Rules, ranging from simple to complex, depending on organizational needs. Rules can be created or copied to suit different requirements. Matcher supports multiple rule types to accommodate diverse organizational needs.

To access the rules, navigate to **Administration>>Matching Rules**. Here, administrators can view rules by reconciliation group, selectable from a drop-down menu, and add new rules from the same page.

![image](https://static.adra.com/adra-assistant/images/645c48be789bdd36b902f32d7d587d61.jpg)

1.  **Shared Rulesets** - Click the tab to view and manage rules that can be applied as sets to various reconciliation groups. To learn more, refer to [Related Articles](#related-articles).
2.  **Select reconciliation group** - Select the reconciliation group to display matching rules for.
3.  **Create rule**
    *   **Copy Rules** - Click to copy rules from another reconciliation group.
    *   **New Rule** - Click to create a new matching rule.
4.  **Select a set of matching rules** - Select a S**hared Ruleset** to be applied to the current reconciliation group.
5.  **Order and active toggle** 
    *   **Handle** \- Click and drag rules to reorder them. The rules are run from top to bottom. The order dictates what transactions are matched first, which impacts the success of the matching rules below it.
    *   **Toggle** \- Disable the toggle (grey) to deactivate the rule. The rule will be skipped when automatic matching rules are run.
6.  **Rules** - Click a rule to view and edit it.
7.  **Action buttons**
    *   **Statistics** \- Click to view a statistical chart of the rules matching success.
    *   **Clone** \- Click to clone the rule. The rule is added at the bottom of the list.
    *   **Delete** \- Click to delete the the rule.

 **BEST PRACTICE**: The order of the matching rules on the **Administration>>Matching rules** page dictates what transactions are matched first, which impacts the success of the matching rules below it.

Add / Edit a Matching Rule
--------------------------

Navigate to **Administration>>Matching rules**. Use the **Select reconciliation group drop-down** to choose a reconciliation group.  
  

To create a new rule, simply click **\+ New Rule**. A new page will open to select the options for creating the new rule. The process for creating new rules is covered over this section, broken down into each part.   
  
To edit an existing matching rule, click the **rule** to edit.

![image](https://static.adra.com/adra-assistant/images/2fca8670155a67a4fad8f9dd841b012e.jpg)  
  

First, administrators will need to name the matching rule. It is recommended to keep this as descriptive as possible. Giving rules names by what they do will help alleviate any confusion and allow the admin to ensure rules are properly ordered.

Administrators also need to choose the source for their matching rule. Note, that the figure shows Ledger vs. Bank. These terms may change based on the settings and terms used in General Settings. Ledger and Bank are the preconfigured sources for Matcher. Once all of the configurations are complete, admins can return to the top of the page and click **Test rule** to ensure it is properly working.

![matching rules new.jpg](https://static.adra.com/adra-assistant/images/e0b845201290488fd7c64b2d3ee6aee9.jpg)

*   **Ledger vs Bank** - Match any accounts from the left side to any accounts on the right side.
*   **Debit vs Credit within one side** - Match debit transactions to credit transactions within one side (Left or Right). Regardless of the source, the debit transactions are always considered as the left side and the credit transactions as the right side.
*   **Sum of transactions within one side** - This rule will sum transactions with the same reference, in one or several fields, within a date range. If the sum is zero, the transactions will be matched.

  
**Apply Rule to One or All Accounts**  
Matching rules can be applied to one or more accounts within the Reconciliation Group. This allows users to run more specialized matching rules for specific accounts only, which improves matching rates.  
  
To apply a matching rule to all accounts in the Reconciliation Group, select **Include all accounts in the matching rule**.  
![matcher rule 1.png](https://static.adra.com/adra-assistant/images/5c93aa99e6229e2e40ab724fbffbf0d1.jpg)  
  
To specify the account or accounts to which a matching rule applies, click **Select the accounts you want to include in the matching rule**.

![matcher rule 2.png](https://static.adra.com/adra-assistant/images/0941eb9342ce50d68371dc406e3e100e.jpg)

### **Ledger Vs. Bank: Date and Amount Matching**

Three options exist under **Date and Amount Matching**. The first option will decide whether the matching should happen based on the Booking or Value date. The second option will decide if the items should have the same date and/or amount or if there can be any deviation. The third option is there to ensure that Matcher does not match items when more than one transaction could fit the rule.

![2024-07-23_13-47-02.png](https://static.adra.com/adra-assistant/images/0059cf821a2f8d124813f05624974651.jpg)

1.  **Which dates should be compared?**
    *   **Booking Date** - The date when an entry is posted to an account in the ledger. This is the primary date used in Matcher.
    *   **Value Date** - This is used if there is a second date present in the import files and needed in Matcher.
2.  **Do you allow date deviation and/or amount deviation between Ledger and Bank (Booking date)?**
    *   **Same Day Only** - This will only allow matching if items have the same date.
    *   **Match Ledger to Bank within a date range** \- Allows transactions to be matched within a date range. To learn more, see [Matcher Matching Rule Date Ranges](#article:kA0Ua0000006sSLKAY@Success-Center).
    *   **Same amount only** - Only match values if they are the same.
    *   **Match with an amount deviation** - Define an allowed deviation between credit and debits when making matches.

![image.png](https://static.adra.com/adra-assistant/images/d42913fa721d0020d326659decc1fd21.jpg)

*   *   Admins must first choose between a variance or a split.
        *   **Variance** - Select when the variance is not expected to materialize from the external source.
        *   **Split** - Select used when you expect the amount to materialize at a point from an external source.
    *   **Save Transaction info. from** \- Select to use the transaction information from the oldest or newest transaction for the deviation item. 
    *   **Add deviation to** - Select which source the deviation will be saved to. 
    *   Match with a deviation, **Match with a percentage deviation**, **or Match with a range deviation**. All three selections are shown below. 

![image.png](https://static.adra.com/adra-assistant/images/81a259c58b0d8dc2ea7d137635cae3b7.jpg)

**Match with a range deviation**  
Enter an amount range the deviation must be within for the transactions to match.  
This option can be used to select a specific deviation by entering the same number in both fields.  
In contrast to the option **Match with a deviation**, you can also enter an uneven range, for example one that starts on -20 and ends on 35.

3.  **Match transactions if only one unique match exists box.**
    *   **Checkmark:** This would ensure that if more than one item could be matched against another, Matcher would choose not to match these items as it is unknown which item it should choose.
    *   **No checkmark:** Matcher will choose one of the possible items to match.

 **BEST PRACTICE**: It is important to determine what the date and amount deviations are from the data. Because multiple rules can be created, start with a narrower rule and then, if needed, add another rule to expand the date deviation if there are still exceptions that would otherwise be matched through automatic matching.

### **Ledger Vs. Bank: Field Matching**

![image.png](https://static.adra.com/adra-assistant/images/c8f4c2aa6b3432e30ccda35fedcc7f77.jpg)

Three options exist under Field Matching which controls what criteria imported items should be matched on.

*   **Match on date, amount -** Selecting this button would allow items to match that have the same amount and date
*   **Match on date, amount, fields -** Selecting this button would allow items to match that have the same amount and date and one or more fields in common. These fields will need to contain the exact same content for items to automatically match. 

![image](https://static.adra.com/adra-assistant/images/383a45e70d3b0d02afb8de44556c3626.jpg)

*   **Match on date, amount and additional field(s) using RegEx (Advanced)** - Choose one or more fields containing common information between the ledger and bank side, i.e., reference field or text field and enter the RegEx Expression.

### **Ledger Vs. Bank: Match Multiple Items**

![image.png](https://static.adra.com/adra-assistant/images/8d03c1805e67ddf04ca5b7a93be42a91.jpg)

Multiple options exist under **Match Multiple Items** which control how many items should be matched. It is possible to have the following matching rules:

*   One to one matching
*   One to many matching
*   Many to one matching
*   Many to many matching

Selections under the **Many** apply to both the Ledger and the Bank settings.

![2024-03-22_8-33-29.png](https://static.adra.com/adra-assistant/images/eca15ac58c6b2af09ff18df1e1e46fda.jpg)

1.  **One**: If one item is to be matched from the ledger or bank account.
2.  **Many:**
    1.  **From and To** \- Enter the range of days to include from within the selected source. To learn more, see [Matcher Matching Rule Date Ranges](#article:kA0Ua0000006sSLKAY@Success-Center).
    2.  **Many Group by Field** \- If more than one item is to be matched from the ledger account to one or more items from the bank. Select the field(s) that items can be grouped by. I.e. the transactions can be grouped and matched by the Ref field.and additionally grouped by the comment field as displayed below.

![2024-03-22_8-38-39.png](https://static.adra.com/adra-assistant/images/8e1bf5396264b7aa794dadd7b50fe4c8.jpg)

In this example, the bank reference field groups items and matches against the ledger, while items are also grouped by the comments field.  
Whether a field is used for matching or not is determined by the [Field Matching](#ledger-vs-bank-field-matching) configurations.  
Hover over the symbols on the right to view if the field is Grouped and Matched by, or only Grouped.

1.  3.  **Many Group by Field using RegEx** - The matching field attribute will be identified using RegEx, allowing for the extraction of a specific segment from the field(s). Multiple grouping and matching fields can be utilized. It is recommended that a Trintech technician provide the RegEx codes. 
        1.  **Required number of transactions in bundle** - Checking this box will require there be a certain number of transactions in a bundle, as seen in the example image below.

![2024-03-22_9-12-09.png](https://static.adra.com/adra-assistant/images/c8d112b74ae90dce943b462dcd78f440.jpg)

 **HELPFUL HINT**: The additional grouping fields can for example enable items to be matched when they need to be grouped by a field in one source and then grouped and matched by another field in both sources. 

In this example, Source 1 items are grouped if Type **AND** Store Number are the same.

![2024-03-22_9-49-27.png](https://static.adra.com/adra-assistant/images/10b15b351a7cd0edcd83142fb3788341.jpg)

The Store Number is then also used to match the items.

### **Debit Vs. Credit Within One Side** 

After the source is selected, all remaining configuration processes are the same as Ledger vs Bank. Refer to the previous sections of this article for configuring those pieces. 

![image.png](https://static.adra.com/adra-assistant/images/e53b2c3cf6bd776829068a4f8fd704c1.jpg)

Two options will exist under **Select Source for matching** which controls if Matcher should match items on ledger accounts or bank accounts. This would match debit against credit items on the side that is chosen for this rule.

1.  **Ledger Accounts:** By choosing Ledger, credit items will be matched against debit items on the Ledger account.
2.  **Bank Accounts:** By choosing Bank, credit items will be matched against debit items on the Bank account.

Note that these terms may vary depending on the fields created under **Administration>>General Settings**. 

 **HELPFUL HINT**: Using user defined fields does not change the rule logic or options available for matching criteria.
