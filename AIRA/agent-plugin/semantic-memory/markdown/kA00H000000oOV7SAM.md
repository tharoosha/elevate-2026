Setup Common Issues with SAML Authentication
============================================

SAML, or Security Assertion Markup Language is an open standard that allows identity providers to pass authorization credentials to service providers to allow for Single-Sign On (SSO).

  
SAML Signature Error: The expected digest algorithm doesn't match the actual digest algorithm
------------------------------------------------------------------------------------------------

  
![image](https://static.adra.com/adra-assistant/images/a09d5669a33f6fb532b0d496563b2dd5.jpg)  
  
This error usually happens when the algorithms configured to use in SAML authentication are not the same from the Adra (SP) configuration portal and ADFS or other Identity Providers (IdP).

  
**How to Fix?**

*   Check the **Secure hash algorithm/signature algorithm** set the **Identity Provider** (e.g. In ADFS, check the **Relying Party Trust** configuration for the **Secure hash algorithm** in the **Advanced** tab)
*   Check the **Signature Algorithm** and **Digest Algorithm** values in the **Federated Identity Provider Policy** in the **Security** tab for the Engagement on the Adra **SETUP Portal**.
*   These algorithm values _must_ be the same on the **SP** (Adra) and the **IdP** (ADFS/Azure AD). The possible values are **SHA1** and **SHA256**.

 

SAML Signature Error: The SAML response isn't signed
----------------------------------------------------

  
![image](https://static.adra.com/adra-assistant/images/eb4b3bf411aca130e2d832722ddb116a.jpg)  
  
This error is shown when the SAML response coming from the Identity Provider (IdP) (e.g. ADFS, Azure AD is not signed but Adra (SP) expects the SAML response to be signed.

  
**How to Fix?**

*   Check the **Federated Identity Provider Policy** in the **Security** tab of the **Engagement Details** page on Adra **SETUP Portal** to make sure the Response signed toggle button is **No**.
*   If the **Having Response signed** toggle button **Yes** is the desired option, make sure the Identity Provider signs the SAML authentication response using the certificates provided by the Adra Federation Metadata XML file.

  
**Note:** If users are using ADFS as the identity provider, by default ADFS will not sign the authentication response. Instead, it will sign the SAML assertions returned in the authentication response. Therefore users must have Response signed toggle button Off unless they have modified ADFS Relying Party Trust configuration to sign the authentication response.  
  
 

SAML Encryption/Decryption Error: The SAML assertion isn't encrypted
--------------------------------------------------------------------

  
![image](https://static.adra.com/adra-assistant/images/d4ee7e34a7d124d476c4e8fd63e0950e.jpg)  
  
This error occurs when the SAML assertions included in the Identity Provider's (IdP) authentication response is not encrypted and Adra (SP) expects the SAML assertions to be encrypted.

**How to Fix?**

*   Check the **Federated Identity Provider Policy** in the **Security** tab of the **Engagement Details** page on Adra **SETUP Portal** to make sure the Assertion encrypted toggle button is **Off**.
*   If users want the **Assertion encrypted** toggle button to be set to **Yes**, make sure the **Identity Provider** is encrypting the SAML assertion when sending the SAML response.
*   Make sure the **Identity Provider** has the encryption certificate configured. Encryption certificate can be found in the **Federation Metadata XML** file.

  
**Note:** If users are using ADFS as the identity provider, if the encryption certificate is used in the Relying Party Trust configuration for Adra, the SAML Assertions will be encrypted by default.   
  
 

SAML Response Status Error: An error SAML response status was received
----------------------------------------------------------------------

  
![image](https://static.adra.com/adra-assistant/images/7e22ffff2add115f6d63eefeb2a14996.jpg)  
  
This error occurs when the SAML authentication response comes in with an error status code. The error response can be caused by a number of scenarios. Navigate to the following MSDN page to [learn more](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-samlpr/96b92662-9bf7-4910-ab16-e1c28bce962b?redirectedfrom=MSDN) .

  
**How to Fix?**

**Note:** If users are using ADFS as the identity provider, by default ADFS does not require the SAML authentication request to be signed. But if the organization requires the SAML has configured the SAML request to be signed, then if Adra (SP) Federated Identity Provider Policy is not configured to Request signed toggle button to **No**, the authentication will fail.

*   ADFS requires the SAML **Request to be Signed**.
*   Make sure the **Request Signed** toggle button is set to **Yes**.
