Task Manager Understanding User Roles and Access
================================================

Roles Overview
--------------

There are five administrative roles and one user role in Task Manager. Administrative roles include **Organization and Engagement Admin**, **Financial Admin** and **Business Administrator**, which are defined in Setup. Section Administrators and Team Administrators have lower-level administrative access and are defined within Task Manager. Admin and non-admin users can be assigned Team Administrator, Preparer, and/or Approver responsibilities within Task Manager. Preparers and Approvers are responsible for tasks assigned to users and/or their team(s). Non-administrators can be assigned Section Admin privileges, which enables them to manage a section of the task Library.

While the **Organization and Engagement Admin** and **Financial Admin** is not part of the Task Manager hierarchy, many administrators fulfill more than one role. For example, the Financial Admin may also be a Business Admin.

   
  
Users can fill more than one role. For example, the Business Admin may also be a Preparer or Approver. Additionally, a Preparer or Approver may also be the Team Admin. The figure below shows the breakdown of the roles.

Administrative Roles
--------------------

### System Administrators

**Organization and Engagement Admin (OEA)** - is responsible for system administration. The SA is the initial user of the system and is typically an administrator or part of the IT staff.

*   Manage employees (including SCIM) and Organization Admins
*   Control SSO/password policies
*   Can see all organization engagements; can create engagements (when permitted)
*   Manage user access to a specific engagement
*   Configure engagement settings (time zone, webhooks, integrations)
*   Limited trust actions (add trust to service-provider organizations; remove Support/Auditor)

The OEA is the first user of the system and is responsible for setting it up by adding users and assigning them access and administrative privileges for applications. However, the OEA cannot activate the roles that are created. Role activation happens only when users complete the registration process by confirming their verification through email.

**Financial admin (FA)** - is responsible for the financial configurations, including: 

*   Create and manage Legal entities
*   Create and manage fiscal years/periods
*   Import and maintain currency rates

The FA is responsible for creating the required legal entities. Accounts and user roles can only be created and assigned after these legal entities are in place.

### Task Manager Administrators

**Business**  **Administrators (BA):** This role is typically assigned to a manager.  
Permissions include:

*   Assigning roles to user profiles.
*   Granting lower-level administrative roles, including Section or Team Admin, to users.
*   Creating and editing task lists.
*   Accessing the Task Manager Administration page.
*   Managing the task **Library**.

The BA can assign user-specific roles for each Library section and team. Business Admins are responsible for the day-to-day management of Task Manager. In addition to managing users, this also includes creating and managing teams, companies, departments, and other administrative functions. Business Admins are also responsible for managing and creating sections within the **Library**, as well as task lists.  

**Section Administrator:** Unlike the BA, the Section Admin can only access certain sections of the Library and can only administer tasks where they are assigned admin rights.   
Permissions include:

*   Creating, viewing, and editing tasks.
*   Starting task lists for sections to which they have access.
*   Managing assigned sections and tasks in the Library.
*   Sending reminders for task completion.

**Team Administrators (TA):** TAs are administrators for a specific team and can only administer tasks in teams where they have the role. This role is not required within Task Manager but is an optional layer of task management if needed.  
Permissions include:

*   Viewing all team-assigned tasks.
*   Editing active team-assigned tasks, such as due date, Preparer, Approver, etc.
*   Sending reminders for task completion

Non-administrative Roles
------------------------

Preparers and Approvers are responsible for completing tasks. Preparers prepare assigned tasks, which are then submitted to the Approver (if an Approver has been assigned). The Approver is responsible for approving or rejecting tasks. Approved tasks are finalized when the required action is completed. If a task has multiple levels of approval, the task will require approval from other Approvers on the team.

*   **Preparer:** Any staff member who completes the task and certifies its preparation for the Approver to verify.
*   **Approver:** Typically, a manager who certifies the approval of the task.

 **HELPFUL HINT**: Standard users can only view tasks assigned to the team they are a part of. This includes if they have team admin or section admin privileges.
