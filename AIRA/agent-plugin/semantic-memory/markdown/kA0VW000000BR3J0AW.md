Setup OKTA SCIM Groups Linking
==============================

In this article, organizational admins can set up SCIM Groups Linking in OKTA. This is a continuation of [Setup SCIM Provisioning Users Using OKTA](#article:kA06S000001DXbPSAW@Success-Center).

Okta SCIM Groups Linking
------------------------

**HELPFUL HINT:**  
Adra supports Group Linking Functionality in OKTA. This feature allows OKTA to retrieve the groups from Adra in a Read-Only mode, and Link them to OKTA-managed groups. 

1.  In Okta, navigate to **Applications>>Push Groups**. 
2.  Click the **Configuration** icon.

![image](https://static.adra.com/adra-assistant/images/8237863d0581db1c5dec895a77e1f1d4.jpg)

3.  Toggle **Rename Groups**: Disabled and **save**.

![image](https://static.adra.com/adra-assistant/images/c7f35a763b2ed505c03779e955c03507.jpg)

4.  Navigate to **Directory**.
5.  Select **Groups**.
    *   When you open **Directory → Groups**, you may see groups that were automatically created/synced from the SCIM app (these appear as **App Groups**). These **App Groups are read-only in Okta** and **cannot be used** for the group you create/link in the next steps.
    *   Use the group filter dropdown and select **Okta Groups**.
        *   **Okta Groups** = groups you create/manage in Okta (this is what you should use for linking).
        *   **App Groups** = groups coming from the SCIM app (these are what exists in **Adra** and are available to link _to_, but not editable/usable as the Okta-side group).

6.  Click **Add group**.
    *   You can link **only one Okta Group** to **one Adra Group**.
    *   The **Okta Group name matters**:
        *   If the Okta Group name **exactly matches** the intended Adra group name, then later (Step 17) the Adra-side selection may be **auto-matched**.
        *   If the name is **different**, you can still proceed and **link manually** later.

![image](https://static.adra.com/adra-assistant/images/98e7010c2adf311e17c092e346e6f9b6.jpg)

7.  Add a new **group**. Remember: a group can only be assigned one role!
8.  Click **Save**.

![image](https://static.adra.com/adra-assistant/images/113ca601ab5e2bba171d7c319de2d7c5.jpg)

In this scenario, we added a group called Adra Administrators.

![image](https://static.adra.com/adra-assistant/images/7447c81ce817db9a7b656fc50771f684.jpg)

9.  Once the group is created, it is possible to assign people from the Directory.
10.  Navigate to **Directory>>Groups>>People tab** and click **Assign people**.

![image](https://static.adra.com/adra-assistant/images/85befd0ee74f3508bb889f4804264c80.jpg)

11.  **Select** people by clicking the **+** button.

![image](https://static.adra.com/adra-assistant/images/bb1cb79991c052d03b5d5e004479333a.jpg)

12.  In this scenario, we assigned Trantow Admin to the Group. Click **Done**.

![image](https://static.adra.com/adra-assistant/images/cc90d87365d2a414f2e9d49b9c3881ea.jpg)

13.  View the assigned people in the **Directory>>Groups>>People tab**.

![image](https://static.adra.com/adra-assistant/images/0b52bf4f8929e5eff34fff71618450df.jpg)

14.  **IMPORTANT**: Only People assigned to the Application will be processed by the Group Linking. Remember to assign all people from the group to the application as well!

![image](https://static.adra.com/adra-assistant/images/1b4fe0dc11db37e176af10750c7f346c.jpg)

15.  Navigate to **Application>>Push Groups**.
16.  Find the group you want to link and select **Link Group**.
17.  Click **Save**.

![image](https://static.adra.com/adra-assistant/images/81311b46e60face0c739e2d650e7a896.jpg)

**BEST PRACTICE: Standalone Engagement Notes**

If you are using SCIM groups without an Organization Configuration, only with a single Engagement, and you will be using the Engagement Admin Group for multiple Engagement Admins: 

It is recommended to add the OKTA User that you first used to setup the SCIM Provisioning into the Engagement Admin Group, so that your Group in OKTA keeps track of the first user roles that existed before Group Linking was set.
